## Модель Матричной Факторизации (SVD)
### Цель

Предложить к просмотру пользователю фильмы на основе его оценок

### Данные

Дата сет разбивается на 3 выборки: train,test и validation. В соотношении 80%,10% и 10%.
В саму модель мы передаём train выборку которая выглядит как:


| User_id | Movie_Id | Rating |
| ------- | -------- | ------ |
| 1       | 1        | 4.0    |
| 1       | 4        | 3.0    |
| 1       | 7        | 3.0    |
| 2       | 1        | 5.0    |
| 2       | 3        | 5.0    |
| 3       | 2        | 3.0    |

Уже в самой модели происходит предобразование этих данных в разряженную матрицу формата:
`R` размерности `n x m`:

- `n` — количество пользователей.
- `m` — количество фильмов.
- `R[i][j]` — известная оценка, которую пользователь `i` поставил фильму `j`. 
### Метрики
В качестве метрик мы выбрали 
- Precision - доля релевантных среди найденных.
- Recall - доля найденных от всех релевантных.
- MAP - усреднённая точность по всем запросам.
- NDCG - учёт порядка и важности найденного.
- Accuracy - доля всех правильных предсказаний.
Посмотреть результаты метрик можно в [EVALUATION](EVALUATION.md)
### Ограничения
- Сложность в вычислениях: При увеличение масштаба данных прямое вычисление становится очень затратным.
- Статичность: Модель необходимо переобучать при поступление новых данных.
- Одномерность: Модель хорошо понимает какие фильмы нравятся пользователю но она не учитывает когда в при каких условиях он предпочитает то или иное.
- Зависимость от количества данных: Модель лучше работает когда пользователь максимально активен но также получается ошибки если пользователь делал лишь 1-2 оценки 
### Риски
- Проблема холодного старта: Для пользователей которые совершили мало оценок модель будет часто ошибаться из за нехватки данных.
- Проблема снежного кома: Модель будет рекомендовать пользователям только те жанры которые им ранее понравились при этом не рекомендуя другие. Из за чего в какой-то момент пользователь будет смотреть только какой-то 1 жанр. Аналогично и с фильмами если фильм некто не оценивал он не за что не будет рекомендоваться людям.
- Модель не видит контекста: Модель не имеет доступа к данным по авторам и т.д. и она не понимает что пользователь предположим фанат определённого автора.
## Item-based Collaborative Filtering
### Цель

Предложить к просмотру пользователю фильмы на основе его оценок

### Данные

Дата сет разбивается на 3 выборки: train,test и validation. В соотношении 80%,10% и 10%.

| User_id | Movie_Id | Rating |
| ------- | -------- | ------ |
| 1       | 1        | 4.0    |
| 1       | 4        | 3.0    |
| 1       | 7        | 3.0    |
| 2       | 1        | 5.0    |
| 2       | 3        | 5.0    |
| 3       | 2        | 3.0    |

Посмотреть результаты метрик можно в [EVALUATION](EVALUATION.md)
### Ограничения
- Сложность в вычислениях: При увеличение масштаба данных прямое вычисление становится очень затратным. Так как сложность расчётов O(m²).

- Смещение в сторону популярного:  Популярные фильмы имеют большую схожесть с другими только за счёт большого количества людей его оценивших.

- Проблема холодного старта: Для пользователей которые совершили мало оценок модель будет часто ошибаться из за нехватки данных.
